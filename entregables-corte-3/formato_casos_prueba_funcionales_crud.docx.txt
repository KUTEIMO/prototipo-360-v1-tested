1. DENOMINACIÓN TÉCNICA Y MARCO METODOLÓGICO
¿Cómo se llama oficialmente este tipo de prueba?Este instrumento se denomina oficialmente Especificación de Casos de Prueba Funcionales (Functional Test Cases), enmarcado dentro de las Pruebas de Sistema y Aceptación de Caja Negra (Black-Box Testing) según el estándar del Ciclo de Vida de Pruebas de Software (STLC) y la norma ISO/IEC/IEEE 29119.
Estructuración del CRUD por Caso de Prueba Atómico:Un Requerimiento Funcional (RF) describe la capacidad general del negocio (por ejemplo, RF-01: Gestionar Pacientes). Sin embargo, NO se debe crear una sola prueba para todo el requerimiento. Cada una de las cuatro operaciones del CRUD (Crear, Leer/Consultar, Actualizar/Editar, Eliminar/Inactivar) requiere de un Caso de Prueba independiente y atómico, debido a las siguientes razones técnicas:
Diferencia de Precondiciones: Para 'Eliminar' se requiere que el registro exista previamente en base de datos; para 'Crear', se requiere que el formulario esté limpio y el registro no exista.
Diferencia de Endpoints HTTP y Lógica Backend: Crear invoca métodos POST (HTTP 201), Leer usa GET (HTTP 200), Actualizar usa PUT/PATCH (HTTP 200) y Eliminar usa DELETE (HTTP 200/204).
Aislamiento e Identificación de Fallos (Trazabilidad): Si la función 'Eliminar' falla pero la función 'Crear' funciona perfectamente, el defecto se reporta exclusivamente sobre la operación de eliminación sin bloquear la aprobación de la creación.
Independencia de Datos de Entrada: Crear requiere la captura y validación de múltiples campos; Eliminar requiere únicamente el identificador clave (ID/Cédula) y confirmación.

3. EJEMPLO DEMOSTRATIVO DILIGENCIADO: DESGLOSE COMPLETO DE UN CRUD
A continuación se presenta el ejemplo completo de cómo se desglosa el requerimiento RF-01: Gestión de Expedientes de Pacientes (Sistema SITR - Telemedicina Rural) en cuatro (4) casos de prueba individuales, uno para cada operación del CRUD:
Caso de Prueba 1: Operación CREAR (Create)
ID CASO DE PRUEBA:
CP-RF01-C01
MÓDULO / RF:
RF-01: Gestión Pacientes
OPERACIÓN CRUD:
CREAR (Create)
PRIORIDAD:
Alta (Crítica)
NOMBRE DEL CASO:
Registrar nuevo expediente de paciente con datos completos y validaciones de formato.
PRECONDICIONES:
Usuario con rol 'Médico Rural' o 'Auxiliar' ha iniciado sesión en el sistema SITR. El paciente con cédula '1090123456' NO existe en la base de datos.
PASOS Y ENTRADAS:
1. Navegar al módulo 'Pacientes' -> Clic en el botón '+ Nuevo Paciente'.2. Ingresar Cédula: '1090123456', Nombres: 'Carlos Alberto', Apellidos: 'Pérez Gómez', Fecha Nac.: '15/05/1988', Municipio: 'Tibú'.3. Clic en el botón 'Guardar Registro'.
RESULTADO ESPERADO:
El sistema retorna un mensaje de confirmación 'Paciente registrado exitosamente' (HTTP 201 Created), genera el token de expediente único y el registro aparece inmediatamente en la lista.
EVIDENCIA OBSERVADA:
Registro guardado correctamente en 1.2 segundos. Se verificó en BD Postgres la creación de la fila en la tabla 'pacientes' con estado 'ACTIVO'.
ESTADO FINAL:
APROBADO (A)

N/A (Sin defectos)
